# DataBridge 答辩讲述提纲（技术内容初版）

> 本提纲引用仓库中已完成的实验；学校封面信息仍须按正式模板填写。讲述中严格区分“已实现/已测试”和“尚未实现”，不把 Debezium 的 Binlog 解析说成自研。

## 1. 题目与一句话问题

**题目：**基于 Spring Boot 的异构数据库迁移与增量同步平台的设计与实现。

**口述：**“我做的是把 MySQL 的一张业务表迁到 PostgreSQL。难点不是复制一次数据，而是复制期间有人继续修改源表时，怎样不漏数据、不错序；程序中断之后，怎样知道从哪接着做。”

## 2. 场景和范围

画两个数据库，中间标出历史数据与后续变更两条流。明确只做 MySQL→PostgreSQL、单机单表、固定表结构、不可变有符号 BIGINT 主键、预建空目标表。此限制是为了把可靠衔接验证清楚，不是声称支持所有数据库。

## 3. 最关键的反例

展示同一行：全量线程读到旧值 A；源端改成 B；CDC 若立刻写目标为 B；晚到的全量批次再写 A，目标倒退。说明 UPSERT 只处理主键冲突，不决定两个通道的业务先后。这个反例引出核心设计。

## 4. 核心方案

用一张图展示：先启动 Debezium 并通过探针确认捕获；CDC 事件只入持久日志；JDBC 按主键分批全量；全量完成后回放事件；追平后持续同步。指出 Debezium 只负责解析 Binlog，自研部分为事件可靠存储、复制检查点、调度、应用游标和校验。

## 5. 断电/重启为什么可恢复

讲两对同事务提交：目标行与全量检查点；事件应用与应用游标。若事务失败，两者都不前进；若已提交，重启从已记录位置继续。事件键与唯一约束处理 Debezium offset 周期刷盘后的重发。不要称跨数据库全局 Exactly Once。

## 6. 为什么能做一致性报告

要求源端停写。先发探针、等待其被捕获并应用；分页扫描比较两库；最后再发探针并等待。若两个探针间捕获到业务事件，只返回 `INCONCLUSIVE`，不误报“一致”。若真正有差异，只记录主键和差异列名，不保存业务原值。

## 7. 实际可演示功能

在本机网页选择演示表、建任务、启动、看状态从复制到持续同步；展示持久检查点和事件积压；源端改一行、目标端出现新值；停写后点校验，展示 `CONSISTENT` 报告。演示时只用三行演示表，避免现场网络或百万行实验耗时影响答辩。截图见 `docs/screenshots/`。

## 8. 测试和实验

目前已有原 50 项后端单元/真实双库集成测试、9 项前端测试，以及进程强制终止后的本机手工恢复演示。正式全量性能已采用三规模、两批次、每组三次完成：100 万行在批次 500/1000 下的中位耗时分别为 344.829 秒和 264.094 秒，详见 `experiments/full-copy-report.md`；这不含 CDC，也不是端到端迁移耗时。独立 CDC 延迟实验三轮各 100 条，合并样本可观察延迟 P50/P95/P99 为 341.292/577.380/630.625 ms，包含源提交调用与目标轮询误差。三个故障窗口各强杀子 JVM 三次，恢复后 9 次差异行数都为 0；全量、CDC 入库、回放的中位恢复耗时分别为 14.420、4.346、4.231 秒，口径包含 JVM 启动，且全量剩余 990 行所以不能横向比较。讲述技术重复与环境限制，避免只挑最好的一次。

## 9. 技术贡献与不足

贡献是限定场景下可运行的“全量—增量无空窗衔接 + 持久化恢复 + 静默校验”闭环，不是新发明 CDC。尚无跨进程 fencing、网页登录、自动建表或在线强一致校验；规模和类型支持有限。下一步核对学校模板并完成论文定稿，再决定是否拓展功能。

## 常见提问的简短回答

1. **为什么不直接用 Debezium 全量快照？** 本课题需要展示自研 JDBC 全量分页、批次检查点和独立 CDC 衔接的设计与验证，因此使用 Debezium `no_data` 只负责捕获变更。
2. **为什么不用时间戳记哪些行变了？** 时间戳依赖业务表都正确维护字段，且不能自然表示删除；Binlog 捕获数据库真实增删改事件。
3. **是不是 Exactly Once？** 目标端批次和游标在同一事务，事件稳定键去重，但源 Binlog、Debezium offset 与 PostgreSQL 目标事务没有全局原子提交，因此不做端到端 Exactly Once 承诺。
4. **为何校验时必须停写？** 两个数据库没有跨库一致性快照，扫描期间源端写入会使两个读取时刻不同；双探针能发现窗口内事件并返回不确定，而不是假装得到确定性结论。
5. **为什么只支持单表？** 多表还要处理外键顺序、跨表事务和 DDL，增加的问题与当前核心闭环不同；先在单表边界把正确性做实。
